第 1 课：把 AI ChatKit 当作一条生产线

目标不是记住框架名，而是能回答：当我发送一句话时，究竟是谁在决定、谁在查资料、谁在把结果送回屏幕？

先记住一张图

你输入问题 ↓ 前端把问题送到后端 ↓ Agent 让 LLM 判断：直接回答，还是调用工具？ ↓ ↓ 直接回答 Tool 查询 SQLite 或 Chroma ↓ ↓ LLM 根据工具结果写最终回答 ↓ SSE 逐段送回浏览器

这就是将来要替换为 ResearchPilot 的骨架；今天只认识角色，不学习实现。

动手观察：3 分钟

  1. 确认服务已启动，打开 http://localhost:3000。
  2. 发送一个不需要资料的问题：“你能做什么？”
  3. 再发送一个明显需要资料的问题：“请查询员工年假规定。”
  4. 观察第二次回答前，界面是否出现 Tool 调用折叠面板；展开它。

你不是在读代码，而是在观察 Agent 的可见行为：一次是 LLM 直接回答，一次是 LLM 先发出“查资料”的行动请求。

把观察翻译成人话

  • LLM（当前 DeepSeek）：像研究助理，决定是否需要证据。
  • Tool：像已授权的实验仪器；模型不能自己查数据库，只能请求 Tool。
  • bge-m3 + Ollama：把“年假规定”与手册文本变成可比较的数字表示。
  • Chroma：像按语义找资料卡片的档案柜。
  • LangGraph：像实验流程图，限制“思考 → 查资料 → 再思考”的顺序。
  • SSE：像实时传送带，不等最终答案全写完才送到屏幕。

检索练习：先自己回答

用一句话回答下面三题，然后发给我。我只检查理解，不要求术语完美。

完成后再展开：自检方向

1：不依赖手册证据的一般问题。2：检索前需要把查询编码为向量。3：DeepSeek；更准确地说，是 LLM 在 Agent Graph 允许的 Tool schema 范围内作出调用决定。
