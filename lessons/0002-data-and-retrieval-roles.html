AI ChatKit · 黑盒课程 02 · 约 12 分钟

谁负责什么？

你的目标不是记术语，而是能在 ResearchPilot 出问题时，迅速知道该查“哪一层”。

本课的单一收获：能区分 DeepSeek、Ollama/bge-m3、Chroma 与 SQLite 的职责，并用现象判断检索链是否参与了回答。

先做一个真实对比

1
确认项目已启动，打开 http://localhost:3000。
2
新开对话，问：“用一句话解释什么是向量数据库？”
观察：它可能直接回答；这类问题不需要你本地《员工手册》里的证据。
3
再问：“请查询员工年假规定，并告诉我依据。”
观察：界面应出现工具调用；它表示 Agent 正尝试从本地知识库找材料。
4
把两次观察各记成一句话：哪次看到了工具？哪次更依赖本地资料？

把观察翻译成系统职责

第二个问题的理想链路是：DeepSeek 判断需要查资料 → Ollama 运行 bge-m3 → Chroma 找到相近手册片段 → DeepSeek 组织答案。

SQLite 不在这条“查手册”的主链上；它更像系统的登记簿，适合保存用户、会话或任务等结构化记录。详见 数据与检索职责速查表。

30 秒自测

情景 A：Ollama 没启动，但 DeepSeek API 正常。问“员工年假规定”时，最可能少了什么能力？

情景 B：Chroma 中没有导入员工手册，但其他服务正常。最合理的判断是？

情景 C：要保存“某份论文由谁上传、什么时候处理完成”，优先放在哪里？

你可以这样向我汇报

“我观察到：……。我的判断是：年假问题依赖……；如果 Chroma 为空，……。”

不用答得完美。把你的观察发给我，我会只纠正关键概念，然后带你进入第三课：Agent 为什么会自己决定调用工具？

主资料：Chroma 官方 Query and Get 文档。它说明查询文本会经 embedding function 转化后进行向量检索。补充：Ollama 官方 Embeddings 文档。
