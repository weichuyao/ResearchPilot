数据与检索职责速查表

ResearchPilot 以后也会沿用这套分工：普通数据、原始资料、语义索引、最终回答，各自放在合适的位置。

组件它保存或产生什么它不负责什么
SQLite
未来 PostgreSQL		结构化记录：用户、会话、任务、文档登记信息。不理解“意思相近”。
原始文档PDF、DOCX、Markdown 的完整内容；是可追溯的事实来源。不能直接高效按语义找段落。
Ollama本机模型运行环境；把请求交给已安装的模型。它不是某一种模型，也不是数据库。
bge-m3把一个段落或问题变成向量（数字坐标）。不写最终自然语言回答。
Chroma保存“文本块 + 向量 + metadata”，按相似度取回候选段落。不判断回答是否真实、完整或有逻辑。
DeepSeek理解问题、决定是否调用工具、阅读取回资料并组织回答。不天然知道你的本地知识库里有什么。

一条检索链

问题 → Ollama 运行 bge-m3 → 查询向量 → Chroma 找相近文本块 → DeepSeek 基于文本块回答。

“向量数据库”不等于“把文档丢进去就会准确回答”。能否检索到正确证据，取决于文档解析、切块、metadata、嵌入模型与检索策略；能否据实回答，还取决于 Agent 的回答约束。
